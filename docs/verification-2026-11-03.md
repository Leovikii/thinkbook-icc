## 两个 P3 配置具体变了什么

两边文件长度、其他标签均相同，变化集中在 ICC 色彩矩阵标签及头部 16 字节 Profile ID。

| 文件 | 大小 | 参数变化 | 差异字节总数（含 Profile ID） |
| --- | --- | --- | --- |
| `TPLCD_8AD7_DCIP3.icm` | 35,888 | `rXYZ`、`gXYZ`、`bXYZ` | 28 |
| `TPLCD_8AD7_DisplayP3.icm` | 35,896 | `rXYZ` | 20 |

DisplayP3 的红色 XYZ 从 `(0.5150909424, 0.2411804199, -0.0010375977)` 变成 `(0.5150909424, 0.2411804199, 0)`，即红色 Z 分量被截断到零。本机 DCIP3 的三个 XYZ 色柱也全部变得与本机 DisplayP3 相同；预装备份中两者矩阵不同。

两套文件的内部 Profile ID 均通过 ICC 算法验证：将头部 profile flags、rendering intent 和 Profile ID 字段清零后计算 MD5，均等于各自保存的 Profile ID。这支持“内容被有意识地重写并重新生成校验值”的判断，不像随机复制损坏；**无法据此识别修改者、软件或具体原因**。本机两个文件的修改时间分别是 2026-04-27 20:29:25、20:32:21，时间戳只作为线索。

普通逐字节复制不应改变这些字段。负 XYZ 分量本身也不足以判定预装文件错误：ICC 官方技术说明记录了 P3 等色域在色适应变换后产生负 XYZ 的情况，以及将其截断到零会影响往返转换。因此不自动“修复”预装原件，也不把本机版本当作更正确的版本。参考 [ICC：Guidelines on the use of negative PCSXYZ values](https://www.color.org/technotes/Guidelines_on_the_use_of_negative_PCSXYZ_values.pdf)。

这次验证确认文件来源、字节差异和两个 P3 文件的内部 ID 一致性，不能替代色度计对实际显示效果的测量。
